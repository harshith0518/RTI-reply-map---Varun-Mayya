# Submission QA checklist

## Product truthfulness

- [x] Every screen identifies the product as an independent hackathon demonstration.
- [x] Synthetic data, no government connection, no submission, and no legal advice are disclosed.
- [x] All sample PDFs are watermarked and contain no real personal information.
- [x] The product says “suggested” or “proposed” rather than presenting a legal verdict.
- [x] Question 3 remains **Partially addressed** because the total is present but the requested calculation record is absent.

## Core journey

- [x] The main flow works without authentication.
- [x] Questions retain stable numbers across branches, mapping, evidence, review, and summary.
- [x] Each result names its reply file and registration branch.
- [x] Exact evidence includes a passage, location, confidence, and missing detail when relevant.
- [x] Any mapped question can be opened for evidence and review.
- [x] A human label override changes the effective summary without changing source evidence.
- [x] Reviewer notes are stored locally and included in the reviewed summary.
- [x] Reset restores the untouched synthetic case.

## Quality gates

- [x] Seven domain tests pass for Maya, Nisha, and Asha.
- [x] Production build completes successfully.

- [x] Buttons, radios, text areas, progress, focus, and browser hash navigation use semantic HTML.
- [x] The three source PDFs render cleanly on all six pages.
- [x] Social preview uses the exact product title and a dedicated preview image.

## Before submitting

- [ ] Open the final public URL in a private browser window.
- [ ] Confirm the public URL requires no account or access request.
- [ ] Play the full 60-second demo once against the deployed build.
- [ ] Paste the public URL and the summary from `project-summary.md` into the submission form.
- [ ] Record the video at 1080p with browser zoom at 100% and notifications disabled.
